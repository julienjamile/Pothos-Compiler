## Implementation map

- `backend/pothos/lexer/charsets.py` defines ASCII character classes, whitespace, delimiters, comment classes, and transition input sets.
- `backend/pothos/lexer/tokens.py` defines token type names, reference tuples for reserved words/symbols, and the immutable `Token(type, lexeme, line, column)` record.
- `backend/pothos/lexer/errors.py` defines `LexicalError(message, line, column, text)`.
- `backend/pothos/lexer/lexer.py` is the state machine: shared start state 0, TD1 reserved words, TD2 symbols, TD3 identifiers, TD4 numeric literals, TD5 strings/comments. `_go`, `_accept`, `_error`, and `_where` manage transitions, token acceptance/retraction, recovery, and source positions.
- `RESERVED_WORDS` and `RESERVED_SYMBOLS` are reference lists; the scanner itself recognizes words and symbols through explicit transitions in `lexer.py`. Updating those tuples alone would not add a scanner rule.
- `tests/test_lexer.py` is the only current test file and covers examples, selected errors, positions, escapes, keyword prefixes, and whitespace trace paths. It does not currently establish conformance for every transition edge or every delimiter-set member.

## Current regression result

Command: `.venv/Scripts/python.exe -m pytest tests/test_lexer.py -q`  
Result: **8 failed, 52 passed**. Seven parameterized valid examples fail at EOF after `]` or `)`; the remaining failure expects `+25` to be a lexical error. This is the same baseline recorded in P-02. No source or tests were modified during this audit.

Additional read-only check: a one-off script passed all **54** reserved-word and reserved-symbol catalog entries individually when each was followed by a space. This confirms those isolated spellings are recognized; it does not prove delimiter-table or sequence conformance and is not a substitute for regression tests.
